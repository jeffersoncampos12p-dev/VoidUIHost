# Internationalization (i18n)

VoidUI includes a built-in internationalization system that supports multiple languages. The library ships with English (en-US), Portuguese (pt-BR), and Spanish (es-ES) translations and allows you to add additional languages at runtime.

## Supported Languages

VoidUI includes translations for the following languages out of the box:

- **English (en-US)** — The default language and fallback for all translations
- **Português (pt-BR)** — Brazilian Portuguese translation
- **Español (es-ES)** — Spanish translation

These translations cover the built-in UI strings used by VoidUI components, such as button labels, dialog text, and other interface elements. You can extend these translations with your own application-specific strings.

## Setting the Language

You change the active language using the `SetLanguage` function. When you change the language, all components that use translated strings update to display the new language.

```lua
VoidUI:SetLanguage("pt-BR")
```

After calling this function, all components that display translated text will update to show the Portuguese translations. Components that use hardcoded text (text you set directly in component configuration) will not change — only strings that go through the translation system are affected.

## Getting the Current Language

To get the current language code, use the `GetLanguage` function:

```lua
print(VoidUI:GetLanguage())  -- "pt-BR"
```

## Listing Available Languages

To get a list of all available language codes, use the `GetAvailableLanguages` function:

```lua
for _, lang in ipairs(VoidUI:GetAvailableLanguages()) do
    print(lang)
end
-- en-US, pt-BR, es-ES
```

## Translating Strings

You translate a string key using the `Translate` function. The function looks up the key in the current language's translation table and returns the translated value. If the key is not found in the current language, it falls back to the English translation. If the key is not found in any language, the key itself is returned.

```lua
print(VoidUI:Translate("save_button"))  -- "Salvar" (in pt-BR)
print(VoidUI:Translate("cancel_button"))  -- "Cancelar" (in pt-BR)
print(VoidUI:Translate("nonexistent_key"))  -- "nonexistent_key" (fallback to key)
```

## Adding Custom Translations

You can add your own translations for application-specific strings using the i18n module's `AddTranslations` function. This allows you to add translations for multiple languages at once.

```lua
local i18n = VoidUI:GetI18n()

i18n.AddTranslations({
    ["en-US"] = {
        app_title = "My Application",
        welcome_message = "Welcome to my application!",
        settings_saved = "Settings have been saved successfully.",
    },
    ["pt-BR"] = {
        app_title = "Meu Aplicativo",
        welcome_message = "Bem-vindo ao meu aplicativo!",
        settings_saved = "As configurações foram salvas com sucesso.",
    },
    ["es-ES"] = {
        app_title = "Mi Aplicación",
        welcome_message = "¡Bienvenido a mi aplicación!",
        settings_saved = "La configuración se ha guardado correctamente.",
    },
})
```

Once added, these translations can be used with the `Translate` function:

```lua
print(VoidUI:Translate("app_title"))
print(VoidUI:Translate("welcome_message"))
print(VoidUI:Translate("settings_saved"))
```

## Adding a New Language

You can add an entirely new language to the system using the `AddLanguage` function. This is useful if you need to support a language that is not included with the library.

```lua
local i18n = VoidUI:GetI18n()

i18n.AddLanguage("fr-FR", {
    save_button = "Enregistrer",
    cancel_button = "Annuler",
    ok_button = "OK",
    close_button = "Fermer",
    -- Add all the keys you need
})

VoidUI:SetLanguage("fr-FR")
```

When adding a new language, you only need to provide the keys that your application uses. The translation system will fall back to English for any keys that are not provided in the new language, so you do not need to translate every single key — just the ones that are important for your application.

## Language Change Events

You can listen for language changes using the i18n module's change signal. This is useful for components or logic that needs to react when the language changes.

```lua
local i18n = VoidUI:GetI18n()

i18n.OnLanguageChanged:Connect(function(lang)
    print("Language changed to:", lang)
    -- Update your custom UI text here
end)
```

## Best Practices

Use translation keys that are descriptive and follow a consistent naming convention. A common approach is to use dot notation to group related keys, such as `"settings.title"`, `"settings.save_button"`, `"settings.cancel_button"`. This makes it easier to organize and manage translations as your application grows.

Always provide English translations as the baseline, since English is the fallback language. If a key is missing from another language, the English translation will be used, so ensuring complete English coverage prevents untranslated strings from appearing.

For user-facing text in components, consider using the translation system rather than hardcoding strings. This makes your application accessible to a wider audience and allows for easy localization. However, for text that is specific to your application's domain and unlikely to need translation (such as proper nouns or technical terms), hardcoding is acceptable.

When building components that display dynamic text, use the translation system for any static labels or prompts, and pass dynamic values as parameters. This keeps the translation system focused on static strings while allowing dynamic content to be displayed in whatever form it takes.
